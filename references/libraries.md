# Shared library map

Use only the entries relevant to the change. These are source-backed orientation notes from **2026-11-05**, not minimum-version promises or a mandate to add dependencies. Links pin the inspected revisions; inspect current source and the target consumer before implementing against an API.

| Library | Reuse and boundary |
| --- | --- |
| [lispm-kit](https://github.com/LispMachineLab/lispm-kit/blob/a6cbb26aa2de9429981c9dda680f64c2664e6542/README.org) | `lispm-kit-define-commands` declares commands once; the mode's `lispm-kit-commands` property supplies plain metadata to hosts. `lispm-kit-i18n-define` and `lispm-kit-tr` provide domain-based translation; apps own their catalogs. Kit owns no Desktop presentation policy. |
| [lispm-ui](https://github.com/LispMachineLab/lispm-ui/blob/0018caafab0db3da1988373f5f2c947cf0225be2/README.org) | Common controls, forms, alerts/confirmation, menus, file dialogs, adjacent tabs (`lispm-ui-tabs`, `lispm-ui-tabs-width`), child-frame minibuffer/echo fields (`lispm-ui-field-make`, `lispm-ui-field-dispose`, `lispm-ui-field-enable`), layout, palettes, icons, lists, and rendering fallbacks. Use public `lispm-ui-*` operations such as `lispm-ui-confirm` and `lispm-ui-choose-file`; hosts customize public hooks such as `lispm-ui-alert-function`. Depends on Kit, not Desktop, GL, or Kernel. Classic appearance is available independently of Desktop. |
| [lispm-auth](https://github.com/LispMachineLab/lispm-auth/blob/bbd3aae159690b60b2c78c5b962c763e90894d5a/README.org) | Password-encrypted secret store (`lispm-auth-change-password`, `lispm-auth-lock`, `lispm-auth-unlock`), per-app startup password declarations (`lispm-auth-start-apps`, `lispm-auth-app-requires-password-p`, `lispm-auth-set-app-requires-password`), and handlers for `lispm-secret-get-functions` and related secret hooks. Uses a standalone compiled Common Lisp (ECL) crypto service with statically linked `libsodium` (Argon2id and XChaCha20-Poly1305) acquired explicitly via `lispm-auth-install-service`. Exposes `lispm-auth-page-window-draw-function` for host-framed password pages while working in ordinary graphical or terminal Emacs without Agent or Desktop. |
| [lispm-prebuilt](https://github.com/LispMachineLab/lispm-prebuilt/blob/6a42033b26579ba7648111166e24904f5277182e/README.md) | `lispm-prebuilt-define` describes a native artifact and its source/version selection, checked download/cache, ensure/load operations, and explicit build recipe. Consumers own native sources, releases, and pins. Default behavior downloads checked artifacts; compiler availability does not authorize an implicit build. Ordinary process/curl fallback keeps optional Agent/Kernel acceleration optional. |
| [lispm-kernel](https://github.com/LispMachineLab/lispm-kernel/blob/08992467f07c146e3efda08d40c24f9d843784b7/docs/architecture.md) | Bounded background jobs, session indexing, asynchronous execution/fetch, cancellation/supersession, and budgeted delivery. The inspected runtime is a **separate Common Lisp/SBCL executable**, despite the stale Rust repository description. Elisp callbacks still execute on the Emacs thread and must stay short. Timer scheduling works without Desktop; hosts can inject scheduling. |
| [lispm-security](https://github.com/LispMachineLab/lispm-security/blob/e73576ac7edbea79b2390633c35d2121ee24067a/README.org) | Inventory, scanning/reporting, configuration/code checks, trust pins, explicit OSV lookup, and public inventory/check hooks. Agent tool/MCP guards are optional. Uses Kit and works without Agent or Desktop. Keep scanning, external lookup, and enforcement distinct. |
| [lispm-gl](https://github.com/LispMachineLab/lispm-gl/blob/2ea3ba77ab29ddf9c1f2b4e6f7b0fa9038c3971d/README.md) | OpenGL buffer/canvas API, GPU resources, drawing, and visibility-aware animation. Uses Prebuilt for a Rust dynamic module **inside the Emacs process**; Kernel is not mandatory. Actual canvases require supported Emacs 32+ capabilities/platforms. Package loadability and successful rendering are separate contracts. |
| [emacs-cl](https://github.com/LispMachineLab/emacs-cl/blob/62007715826889b7daaedfd27cbaa9aa864842f1/README.md) | Common Lisp implemented in Elisp, with `emacs-cl-start`, `emacs-cl-command`, and a reusable listener for clients such as MYCIN/SHRDLU. By default, the implementation runs in a **separate batch Emacs**, not SBCL or Kernel. Do not assume complete ANSI conformance. |

## Integration cautions

Kernel currently has its own executable acquisition implementation in [lispm-kernel-program.el](https://github.com/LispMachineLab/lispm-kernel/blob/08992467f07c146e3efda08d40c24f9d843784b7/lisp/lispm-kernel-program.el), and Auth manages its own service archive verification and installation in [lispm-auth.el](https://github.com/LispMachineLab/lispm-auth/blob/bbd3aae159690b60b2c78c5b962c763e90894d5a/lispm-auth.el#L1267). Do not assume either delegates acquisition to Prebuilt. Keep the three Common Lisp runtimes distinct: `emacs-cl` (Elisp in a batch Emacs process), `lispm-kernel` (SBCL background executable), and `lispm-auth` (compiled ECL + libsodium crypto executable). Kernel's [lispm-kernel-desktop.el](https://github.com/LispMachineLab/lispm-kernel/blob/08992467f07c146e3efda08d40c24f9d843784b7/lisp/lispm-kernel-desktop.el) is a legacy-named Agent session adapter, not evidence of a Desktop requirement. Read dependencies and behavior rather than inferring them from filenames.

Prebuilt exposes a host-neutral fetch callback; Kernel can wrap it externally. Do not create a mandatory dependency cycle from optional integration. Native loading, native rendering, and successful background execution need their own capability checks.

Store is [plain catalog data](https://github.com/LispMachineLab/lispm-store/blob/af4901b33edefd127dcde514ab6c63699590c18b/README.org), with package revision pins and install dependencies. Its inspected schema/installer tooling lives in Desktop. That tooling placement is not permission for an app runtime to depend on Desktop, nor a reason to put executable runtime machinery into the catalog. Extract shared catalog machinery only for a concrete consumer need.

Some existing Agent plugins have historical package-header omissions even though they require Agent in code; [Hermes is one example](https://github.com/LispMachineLab/lispm-hermes/blob/4878fa120fc42c80faf9aeaa8f8c773e3c9bb84d/lispm-hermes.el#L37). Audit declarations and actual calls together. Agent's package dependency is `lispm`, not `lispm-agent`.
